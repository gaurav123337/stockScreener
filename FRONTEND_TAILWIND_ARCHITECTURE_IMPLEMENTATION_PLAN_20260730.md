# Frontend Tailwind Architecture Implementation Plan

**Timestamp:** **2026-07-30T08:40:08Z (UTC) | 30-07-2026 14:10:08 (IST)**

## Overview

Modernize the React 18/Vite frontend from global CSS primitives and CSS Modules to Tailwind CSS v4 while completing the in-progress tester feedback workflow. Preserve the current feature-based architecture, API contracts, hash routing, PWA behavior, and uncommitted feedback work.

## Current State Analysis

- `frontend/src/app/router.tsx` lazy-loads feature pages under a shared `AppLayout`.
- Feature, API, type, auth, and query boundaries are already appropriate for the application's size.
- Styling is split across one global stylesheet and seven CSS Modules (976 lines total), with additional inline styles and legacy global utility classes.
- Shared UI concepts (buttons, cards, fields, page headings, loading states) are duplicated instead of represented by reusable React components.
- The feedback submission path is implemented end to end, but the frontend does not enforce its advertised 5,000-character detail limit and the backend trusts the client-supplied plain-text projection.

## Implementation Phases

1. **Tailwind foundation**
   - Add Tailwind CSS v4 and its Vite plugin.
   - Define semantic design tokens and minimal editor-specific base rules in `frontend/src/styles/global.css`.
2. **Shared UI architecture**
   - Add focused UI primitives for buttons, cards, fields, page headings, and loading indicators.
   - Add a small class-name composition helper for conditional utility classes.
3. **Application and feature migration**
   - Migrate layout, auth, recommendation, scan, train, broker, settings, guide, and toast UI to Tailwind utilities.
   - Remove inline presentation styles, legacy global utility classes, and all CSS Modules.
4. **Feedback completion and hardening**
   - Split rich editor behavior into feature-local components.
   - Enforce title/detail limits, show a live character count, improve toolbar semantics, and prevent duplicate submissions.
   - Derive persisted plain text from validated rich-document content on the backend.
5. **Verification**
   - Run formatting, lint, TypeScript checks, production build, Python feedback tests, and the full Python suite.
   - Review the final diff for accidental changes and update this plan with completion notes.

## Technical Considerations

- Use Tailwind v4's first-party Vite integration; no PostCSS or JavaScript Tailwind config is required.
- Keep semantic color tokens in CSS so utility usage remains readable and the dark operational theme remains consistent.
- Keep custom CSS only for document-content elements generated by TipTap, which cannot receive JSX utility classes directly.
- Do not add state management, schema libraries, or a large component system beyond what the current application needs.
- Preserve HashRouter and existing endpoint types for deployment compatibility.
- Continue storing structured TipTap JSON rather than executable HTML.

## Success Criteria

- All React pages use Tailwind utilities and shared UI primitives; no `*.module.css` files or inline presentation styles remain.
- The app remains responsive across mobile and desktop navigation layouts.
- Feedback accepts rich formatting and emoji, enforces 3–120 title and 10–5,000 detail constraints, and resets after success.
- Backend persistence derives feedback text from the submitted document and rejects forged or malformed rich content.
- Frontend lint, typecheck, and production build pass; feedback and existing backend tests pass.

## Completion Summary

- Tailwind CSS 4.3.3 is integrated through `@tailwindcss/vite`; the frontend now uses semantic Tailwind tokens and shared `Button`, `Card`, `PageHeader`, and loading primitives.
- App layout, authentication, recommendation, scan, train, broker, settings, guide, toast, and feedback surfaces were migrated from CSS Modules and legacy utility classes to Tailwind utilities.
- TipTap feedback controls now live in a feature-local toolbar, enforce the 5,000-character detail limit with Unicode-aware counting, validate HTTP(S) links, expose accessible feedback errors, and prevent duplicate submissions.
- The backend derives persisted `plain_text` from the validated TipTap document and rejects malformed, empty, and oversized derived content. Focused tests cover forged projections and malformed nested documents.
- Large route implementations were decomposed into feature-local orchestration, component, hook, configuration, and pure transformation modules. Scan autocomplete/results, settings rendering/patch construction, feedback editor/form controls, and broker credentials/holdings now have explicit ownership boundaries.
- `FE_ARCHITECTURE.md` is the normative frontend reference for module direction, component extraction signals, state ownership, forms, accessibility, Tailwind usage, naming, and required quality gates.
- Verification completed: `cd frontend && npm run format`, `npm run typecheck`, `npm run lint`, `npm run build`, `python -m unittest tests.test_feedback -v`, `python -m unittest discover -s tests -v`, and `git diff --check` all passed. Only `frontend/src/styles/global.css` remains as a stylesheet entry point.
