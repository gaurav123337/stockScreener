# Frontend React Migration Implementation Plan

**Timestamp:** **2026-07-27T20:29:00Z (UTC) | 28-07-2026 01:59:00 (IST)**

## Overview

Migrate the stockScreener frontend from vanilla JS (single 27 KB `web/static/app.js`) to a production-grade **React 18 + Vite + TypeScript** application, preserving all existing functionality and the PWA experience. FastAPI backend (`api.py`) remains the single source of JSON APIs and continues serving the built frontend as static files — single-process deployment is preserved.

## Current State Analysis

- `web/index.html` — 52-line SPA shell with 6 tabs: Recommend, Scan, Train, Brokers, Settings, Guide
- `web/static/app.js` — 475 lines of imperative vanilla JS: hash router, innerHTML rendering, API calls, autocomplete, settings forms, broker flows, PWA install prompt
- `web/static/styles.css` — 145 lines, dark theme, CSS variables, mobile-first
- `web/sw.js` — hand-written service worker (network-first), `web/manifest.json` — PWA manifest
- `api.py` — FastAPI serves `/api/*` JSON + static SPA fallback; mounts `/static`
- Backend API surface (stable, no changes needed):
  - `GET /api/recommend/{symbol}`, `POST /api/scan`, `GET /api/filters`, `GET /api/search?q=`
  - `GET/POST /api/settings`, `GET /api/settings/defaults`, `POST /api/settings/reset`
  - `POST /api/learn/file`, `POST /api/learn/url`, `POST /api/learn`, `GET /api/knowledge`
  - `GET /api/brokers/instructions|status|holdings`, `POST /api/brokers/connect`, `POST /api/brokers/disconnect/{broker}`

## Architecture Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Framework | React 18 + TypeScript | Type safety across the API boundary, component model replaces innerHTML strings |
| Build tool | Vite 5 | Fast HMR dev server, proxies `/api` → `:8000`, small prod bundles |
| Routing | React Router v6 (HashRouter) | Replaces hand-rolled hash router; HashRouter keeps FastAPI static-serving trivial (no history-API fallback needed) |
| Data fetching | TanStack Query (React Query) | Declarative server state: caching, loading/error states, mutations, invalidation — replaces ad-hoc fetch + disabled-button state |
| Forms | React Hook Form + Zod | Type-safe validated forms (settings patch, broker credentials, scan builder) |
| Styling | CSS Modules + design tokens | Ports existing `styles.css` 1:1, scoped per component, zero runtime cost, no UI-lib lock-in |
| PWA | `vite-plugin-pwa` (injectManifest) | Keeps existing network-first `sw.js` strategy as a custom service worker, auto-registers manifest |
| HTTP client | `ofetch` | Tiny typed wrapper with error normalization (replaces the `api()` helper) |
| Lint/format | ESLint (typescript-eslint) + Prettier | Production-level code quality gates |

## Implementation Phases

### Phase 1 — Scaffold
- `frontend/` Vite + react-ts project; path alias `@/`; env-driven API base URL
- Vite dev proxy `/api` → `http://localhost:8000`
- ESLint + Prettier + `tsc --noEmit` strict config

### Phase 2 — Core shell
- Typed API client (`src/api/client.ts`) with `ApiError`
- Domain types mirroring backend payloads (`src/types/`)
- App shell: top bar, install prompt hook, bottom tab bar, toast system (context + reducer)
- Hash routing with lazy-loaded tab routes

### Phase 3 — Feature parity (one component tree per tab)
- Recommend (multi-symbol input → recommendation cards)
- Scan (filter chips, custom where expression, stock-search autocomplete, expandable results table)
- Train (file upload, URL ingest, knowledge base viewer)
- Brokers (instructions + status, connect/disconnect, holdings viewer)
- Settings (RHF + Zod patch builder, reset to defaults, default-universe editor)
- Guide (static content)

### Phase 4 — PWA + integration
- Port `sw.js` into `src/sw.ts` via injectManifest; manifest + icons
- Update `api.py` static serving to prefer `frontend/dist` (fallback to legacy `web/`)

### Phase 5 — Verification
- `npm run build` clean, `tsc` clean, ESLint clean
- Serve via `python api.py`, smoke-test all 6 tabs end-to-end

## Technical Considerations

- **Backend compatibility**: zero API contract changes; types generated by hand from `api.py` response shapes (e.g. `to_scan_row()`).
- **Legacy kept intact**: `web/` stays as fallback until React build is verified, enabling easy rollback.
- **Node requirement**: Node 18+ (Node 20 LTS recommended) — new dev dependency, documented in README.
- **Risk**: settings patch semantics (numbers vs strings vs arrays) must match vanilla behavior exactly — covered by Zod schemas.

## Completion Summary

**Completed:** 28-07-2026 (IST)

### What was implemented
- **`frontend/`** — full React 18 + Vite 6 + TypeScript application, feature-complete against the legacy vanilla SPA.
  - `src/types/api.ts` — hand-written types mirroring every FastAPI JSON payload.
  - `src/api/` — typed `ofetch` client with `ApiError` normalization + per-endpoint wrappers.
  - `src/app/` — app shell: `AppLayout` (top bar + install button + bottom tab bar), `HashRouter` with lazy-loaded tabs, `ToastProvider`/`useToast`, TanStack Query client, `usePwaInstall` hook.
  - `src/features/` — one module per tab: `recommend`, `scan` (chips + custom filter + debounced autocomplete + expandable results table), `train`, `brokers`, `settings` (React Hook Form patch builder preserving legacy number/string/array semantics), `guide`.
  - `src/components/` — shared `Section` + `RecommendationCard`.
  - `src/sw.ts` — Workbox-powered service worker via `injectManifest`, preserving the legacy network-first + auto-reload behavior.
  - Tooling: strict `tsconfig`, ESLint (typescript-eslint + react-hooks + react-refresh, zero warnings) + Prettier.
- **`api.py`** — serves `frontend/dist` when built (manifest.webmanifest-aware, Vite `assets/` layout), falling back to legacy `web/`; no API contract changes.
- **`README.md`** — project layout + frontend dev/build workflow documented.

### Deviations from plan
- **Zod dropped**: settings patch validation is handled by a typed `buildPatch` function instead — lighter and exactly matches the legacy semantics without schema duplication.
- **Vite 6** used (latest) rather than Vite 5 — no functional impact.
- Toast split into `toast.tsx` (provider), `toast-context.ts`, `useToast.ts` to satisfy the `react-refresh/only-export-components` rule.
